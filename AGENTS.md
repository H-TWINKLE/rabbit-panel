# AGENTS.md

High-signal repo notes for OpenCode sessions.

## Fastest accurate workflow
- Backend entrypoint is `backend/main.go`; app wiring and dependency injection live in `backend/config/config.go` (`config.NewApp()` constructs repos/services and Gin engine).
- Frontend build output must go to `backend/dist` (`frontend/vite.config.ts` `build.outDir`), then backend embeds it via `//go:embed dist` in `backend/main.go`.
- If UI changes do not appear in the binary, rebuild frontend before rebuilding backend.

## Commands you should not guess
- Frontend dev (with API proxy): `cd frontend && npm install && npm run dev` (serves on `:3000`, proxies `/api` and `/ws` to `:3958`).
- Backend local run: `cd backend && go run main.go`.
- Full build (frontend + backend): `./rabbit.sh build`.
- Cross-build targets: `./rabbit.sh build all|amd64|arm64|armv7`.
- Skip frontend rebuild when only backend changed: `./rabbit.sh build --skip-frontend`.
- Frontend tests: `cd frontend && npm run test` (watch: `npm run test:watch`, coverage: `npm run test:coverage`).

## Runtime/config gotchas
- Default mode/host/port come from env with fallbacks in `backend/config/config.go`: `MODE=master`, `HOST=0.0.0.0`, `PORT=3958`.
- Multi-node setup requires shared `JWT_SECRET` and `NODE_SECRET` across master/worker; worker also needs `MASTER_URL` and unique `NODE_NAME` (`docker-compose.worker.yml`).
- Node auth is time-sensitive; keep master/worker clocks in sync (documented 1-hour tolerance in project docs).
- Data is local file-based: SQLite at `./data/auth.db` (relative to backend working dir/container workdir).

## Frontend/tooling quirks
- `frontend/src/auto-imports.d.ts` and `frontend/src/components.d.ts` are generated by Vite plugins (`unplugin-auto-import`, `unplugin-vue-components`); do not hand-edit.
- Vitest is configured to include only `tests/**/*.{test,spec}.ts` (`frontend/vitest.config.ts`), so tests outside that tree will be skipped.

## Build/release reality checks
- `rabbit.sh` builds Linux binaries and auto-detects host arch for default target; output lands under `dist/*-release/` and copies host-matching artifact to `./rabbit-panel`.
- Docker image CI only runs on tag pushes (`v*`) or manual dispatch (`.github/workflows/docker-image.yml`), building `linux/amd64` and `linux/arm64`.
